# v1.6.7

Android 10 及以上 · ARM64 · versionCode 67

## 更新内容

本版更新了频段控制所用的外部后端，并把组件诊断集中到日志监控台。多天线测量出错时，现在会记录绑定失败的具体原因、SIM 映射、重连次数和最终结果，便于排查“刷新无效、重启应用后恢复”的问题。

- bunnylock 同步到 2.1.0，接入展锐 AT 后端、联发科未启用频段的识别，以及 LTE/NR 频段合并请求。原有界面按后端能力显示控制项。
- QCOM BAND MENU 核对至 `7e5b9c4`。本轮上游新增内容属于 OpenWrt，手机端 NAS 助手没有新的上游变更。本地助手延长了绑定等待时间，并区分超时、响应格式异常和带 QMI 错误码的基带拒绝。
- VPN 热点从 2.19.1 更新到 2.19.2，更新热点状态回调，并加入系统 IPsec VPN 上游转发支持。上游 3.x 的路由、Root 服务和客户端数据库尚未迁入本项目。
- bunnylock、QCOM BAND MENU 和 VPN 热点日志接入“设置 → 日志监控台”，包括特权助手及热点 Root 服务传回的事件。导出、分享仍经过脱敏，并补充热点口令字段的处理。
- 默认数据卡存在应用记录的锁定、且移动网络持续中断时，显示解除锁定和等待重连的提示。
- EFS 首次备份可以选择是否上传私有云，本地校验通过后可继续启用修改；增加云备份管理，并改进页面进入、备份验证和异常分级。
- 重整中英文 README，按网络观察、控制、路测、Wi-Fi、备份和问题反馈说明实际用途与限制。

## 验证与使用说明

2026-11-20 检查通过：Debug 构建及主应用、bunny-modem、VPN 热点、qcom-efs 的单元测试任务。测试报告共 574 项，571 项通过、3 项跳过、0 失败；另有 20 项原生 QMI 模拟场景和 27 项恢复脚本模拟场景通过。

发布 APK 的内嵌版本为 1.6.7（67），包名为 `com.nvmex.networkhelper`，最低 Android 版本为 10，只包含 ARM64 原生库。APK v2 签名验证通过，证书与已发布的 1.6.1 相同。内置 QMI/EFS 助手与当前源码树中的发布资源逐字节一致；ZIP 内容及校验值也已核对。

本次未连接真机，未执行覆盖安装、基带写入、系统组件停启或恢复。多天线故障是否在原设备上消失，以及各厂商后端、VPN 转发和 EFS 恢复的实际效果，仍需对应设备验证。QMI 的只读重连不会重放锁定写入。

自动错误上报默认开启，可在日志监控台关闭。日志导出和分享会脱敏；云端诊断上传会在能够读取时附带独立的 IMEI1 字段。猎鹰轨迹纠偏默认关闭，开启后随路测录制向高德上传轨迹。EFS 云备份由用户选择。

同步范围、许可证和详细说明见 [第三方声明](https://github.com/mazemingw/oplus-network-helper/blob/v1.6.7/THIRD_PARTY_NOTICES.md)、[bunnylock 同步记录](https://github.com/mazemingw/oplus-network-helper/blob/v1.6.7/bunny-modem/UPSTREAM.md)、[VPN 热点同步记录](https://github.com/mazemingw/oplus-network-helper/blob/v1.6.7/vpnhotspot-mobile/UPSTREAM.md) 和 [诊断说明](https://github.com/mazemingw/oplus-network-helper/blob/v1.6.7/docs/diagnostics.md)。

## English

This release updates the integrated modem backends and routes component diagnostics into the shared console. Multi-antenna failures now retain the binding reason, SIM mapping, reconnection attempts and final outcome.

- Integrated bunnylock 2.1.0, including Unisoc AT support and combined LTE/NR band requests.
- Reviewed QCOM BAND MENU through `7e5b9c4`; new upstream changes target OpenWrt. The local Android helper now distinguishes bind timeouts, malformed responses and modem rejection codes.
- Updated VPN Hotspot from 2.19.1 to 2.19.2, including interface-state callbacks and system IPsec VPN upstream forwarding. Upstream 3.x has not been migrated.
- Added bunnylock, QMI helper and VPN Hotspot root-service events to the diagnostic console, with hotspot credential redaction for exported logs.
- Added a lock-recovery prompt for sustained mobile-network outages on the default data SIM.
- Made EFS cloud backup optional, added cloud-backup management, and improved session entry, local verification and error classification.
- Rewrote both READMEs around usage and device requirements.

The signed APK supplied by the maintainer is published as `app-release.apk` without rebuilding or re-signing it. It is version 1.6.7 (67), requires Android 10 or later, and contains ARM64 native libraries. Its APK v2 signature is valid and matches the certificate of v1.6.1.

On 2026-11-20, the Debug build and all four modules' unit-test tasks passed. Reports contain 574 tests: 571 passed, 3 skipped, none failed. A further 20 native QMI mock scenarios and 27 recovery-script scenarios passed. No physical-device upgrade, modem write or restoration was performed; device-specific behavior still needs hardware validation.

Automatic error reporting is on by default and can be disabled in the console. Exported and shared logs are redacted; diagnostic uploads include IMEI1 in a separate field when available. Falcon track matching is off by default and uploads tracks to AMap during recording when enabled. EFS cloud backup is optional.
