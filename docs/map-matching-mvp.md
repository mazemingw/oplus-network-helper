# 猎鹰轨迹纠偏接入

适用于 1.5.7-dev。运行时已改用高德 Android 猎鹰 SDK，不再依赖 GeoJSON 导入或内置线路片段。原有本地匹配器与 OSM 样本仅保留为开发测试资料，不参与产品的实时纠偏。

## 配置与使用

本地 `local.properties` 配置现有 Android 地图 Key 和猎鹰服务 ID；也可由构建环境传入同名 Gradle 属性：

```properties
AMAP_API_KEY=existing_android_key
AMAP_FALCON_SID=service_id
```

本次已按[服务管理 API](https://lbs.amap.com/api/track/lieying-kaifa/api/service)创建 `OplusNetworkHelper`，sid 为 `1079775`，保存在本机忽略的配置中。Web 服务 Key 只用于这次创建请求，没有写入源码、配置文件或安装包。Android Key 必须在同一应用下具备猎鹰权限，并匹配实际签名 SHA1 和包名。

在设置或地图“地图绘制与探测参数”中打开“猎鹰轨迹纠偏”，默认关闭。开关旁明确说明启用后会上传定位轨迹。仅开始路测打点后启动采集，录制期间切到后台仍继续运行；停止打点立即结束采集并移除实时青色纠偏线，关闭开关或退出页面也停止。未录制时显示“纠偏 · 待录制”，仅浏览地图不会建立或上传轨迹；回读已有记录只查询其云端轨迹。每台安装使用匿名随机终端名，每次采集建立新的云端轨迹，不用 IMEI 或手机号命名。

依照[官方上报流程](https://lbs.amap.com/api/android-track/guide/guijishangbao/start-guijishangbao)，SDK 每 2 秒采集、10 秒上报，使用 HTTPS，离线缓存上限 10 MB。约每 15 秒按[历史轨迹查询接口](https://lbs.amap.com/api/android-track/guide/guijichaxun/lishiguiji)请求最近 3 分钟的数据，启用去噪和绑路，关闭距离补偿。服务错误显示错误码并重试；未配置、无数据、连接中、历史结果分别显示简短状态，点击可查看详情或重试。

官方接口当前仅支持驾车模式，本功能不提供铁路、地铁绑线。云端结果存在采集、上报及查询延迟，不能作为即时高精度定位保证。

## 地图、原始记录与回读

- 青色线表示云端道路纠偏；原始信号颜色轨迹和打点独立保留。
- 云端点只有时间差不超过 1.5 秒、且距离符合定位精度约束时，才可用于对应当前 GNSS 位置；没有时间戳、过期或距离异常的结果不移动当前位置。IMU 估算不强行替换成旧的云端端点。
- 双卡采样仍使用同一原始定位、原始时间和完整信号快照。`map_match` 元数据附带 provider、sid、tid、trid 及原始坐标；没有有效纠偏坐标时不会伪造坐标或道路匹配状态。
- 回读按照记录中的云端 ID 查询，不启动采集、不补上传历史点。续录产生多个云端轨迹时逐一查询；超过 24 小时的时间范围拆分查询。旧记录没有云端 ID 时仅显示原始轨迹。回读需要网络和对应服务仍保留的云端数据。
- CSV 保留原有纠偏列及 `map_match_json`。原始定位和双卡快照的离线回读不依赖高德云端。

## SDK 维护

项目保持现有 3D 地图 SDK 和定位引擎，额外引入官方猎鹰 1.5.0 的 Java 类依赖闭包，避免完整组合包重复引入定位类。来源、校验和、可复现生成脚本见 [SDK 说明](../app/libs/README.md)。Manifest 注册猎鹰定位前台服务，R8 保留 SDK 类；没有把服务管理的 Web Key 放入客户端。

## 交付验证

自动化覆盖云端延迟点拒绝、时空约束、匿名轨迹元数据、续录多轨迹及查询时间分片，并与地图、双卡记录、CSV 和 NRCA 回归一起执行。

2026-10-23：上述回归共 73 项，全部通过；Debug 与启用 R8 的 Release 构建通过。Release 产物未签名，需要沿用原发布证书签名后发布。AVD 检查了中文/英文、深浅主题、横竖屏及短屏幕的两列控件；猎鹰完成终端和轨迹创建，退出地图后采集服务停止。当前 x86_64 AVD 无法加载现有地图 ARM 原生库（`UnsatisfiedLinkError`），底图未成功渲染；SDK 内部关闭模拟定位，因此 AVD 注入的虚拟行驶点不能用于验证完整云端绑路链路。尚未完成真机道路纠偏验收。

AVD 用于检查浮层位置、缩放交互、横竖屏与 SDK 初始化/服务生命周期。模拟器没有 OPPO 工程模式、真实双卡无线测量或车辆惯性传感器，不能替代实车验证。正式交付前应在 OPPO 新旧系统各检查一次：正常行驶生成青色云端结果，断网继续原始记录，恢复后重新同步；切卡和回读不混入其他轨迹；停止/关闭后不再采集；SS-RSRQ、SS-SINR 与系统快照一致。
