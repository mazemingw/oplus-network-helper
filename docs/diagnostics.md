# 全局诊断模块

`App.onCreate` 初始化 `DiagnosticReporter`。全局崩溃钩子先同步保存报告再委托原 handler；当前应用进程的 logcat W/E/F 捕捉已打印的错误及堆栈。logcat 按线程和标签聚合，连续 350 毫秒没有新行后提交一个异常，最多 64 组待合并堆栈；孤立堆栈片段仅记警告，不逐帧自动上传。下次启动读取 Android 的历史 Java/Native 崩溃、ANR。网络拦截器捕捉 IO 异常及 HTTP 5xx。EFS 通过 `DiagnosticEvents` 接入，不创建额外 DIAG 会话，不写 EFS，不重启基带。

捕获已处理但没有打印日志的异常时，其他模块应显式使用公共接口：

```kotlin
DiagnosticReporter.report("module/action", error, mapOf("stage" to "reading"))
DiagnosticReporter.report("module/action", "业务操作失败", mapOf("errorCode" to "E42"))
DiagnosticReporter.breadcrumb("module: 开始读取")
```

不要传入密码、令牌、文件内容或位置。日志采集会再次脱敏；不会读取全设备 logcat、用户文件、原始分区内容或全量 EFS 备份包。Java handler 无法在 SIGKILL 中执行，历史退出原因/原生追踪也取决于系统是否保留；外部系统进程的 Xposed 异常不会自动跨 UID 读取。

处理器、系统和应用诊断在后台读取，附基础 APK 的 SHA-256 以匹配构建；IMEI 只在上传时复用 EFS 已有缓存、当前 EFS 会话的原身份读取及 RootPhone（固定 IMEI1/SIM0）。EFS 身份确认成功时即缓存有效身份，不再等待备份成功；RootPhone 成功读取的 IMEI 另在排除系统备份的私有诊断配置中按机型缓存，来源标为 `diagnostic_cache`。IMEI 不可用时照常上报并标记 unavailable。备份错误额外只读采集 by-name 链接与 rmt_storage/rmtfs 的块设备 FD；保持完整备份门禁，不会为了上报而放开写入。

设置页右上角日志图标进入独立监控台，旧设置卡片与 EFS 菜单日志入口均已移除。监控台分信息、警告、错误三级，筛选后可清除、复制、脱敏导出/分享或上传云端；上传成功显示可复制的回执并保留最近回执。开发者在后台使用 `node find-diagnostic.js 回执码` 定位私有压缩文件。自动上报开关移动到监控台，默认开启；关闭时仍可主动上传。

监控台内存/磁盘上限 16 MiB，另有 12800 条记录上限，每条摘要 1200 字符、详情 6000 字符；按 UTF-8 和 JSON 转义开销计量，超限滚动移除最旧记录。同源同内容在 60 秒内合并计数，并归一化图形对象地址。新增日志每秒最多 30 条，UI 最多每 500 毫秒刷新，磁盘最多每 5 秒写入。图形/WebView、SettingTrigger 等已知厂商反射与性能噪声降为信息，不当成应用错误；预期基带拒绝为警告，致命异常仍保留错误级别。自动报告同类每 10 分钟最多一份、全局每小时最多 20 份，配额持久化，重启和清除日志不会重置；离线报告池最多 40 条 / 8 MiB，通过 JobScheduler 指数退避上传。

“清除”删除控制台、本地报告和待发记录，并取消旧请求；不会删除分区备份。导出、手动上传和分享缓存同步采用 16 MiB 上限，缓存最多 5 份；日志过大无法通过系统剪贴板复制时提示导出。EFS 文本和后台快照日志分别截尾，日志目录最多 16 份 / 4 MiB；原生 helper 当前日志约 1 MiB 轮转，并对连续重复行节流。旧版错误报告迁移为分级记录，已有待发系统噪声不再自动上传。

EFS 退出采用断开完成后的单次导航回调，不在共享 ViewModel 中保留退出标志；重进根据当前会话状态连接/重连并验证备份。进入与 ON_RESUME 的重复回调合并，连接中不重复启动。完整备份和高通平台门禁继续生效。

分区备份采用运行时发现：读取 `/sys/class/block` 的物理分区元数据，并合并通用、bootdevice、platform 下的 by-name 别名；将 rmt_storage/rmtfs 实际打开的物理分区纳入备份，包含未预置名称的分区，并补齐已发现分区的 A/B 对应槽位。已有名称与 EFS/NV 名称模式仅作为额外线索，不再限制新格式可备份的名称；不会据此备份整盘或 userdata。无法映射到物理分区、映射歧义、超出格式容量或采集期间拓扑变化仍判失败。

新分区清单使用 schema 2，记录发现方式、UUID、别名、发现原因、设备、大小和 SHA-256。导入按清单接收镜像，上限为 128 个分区、每分区 2 GiB、镜像合计 4 GiB、云端压缩包 2 GiB；名称、路径、数量、重复项和完整性仍严格校验。旧 schema 1 归档保持兼容并沿用旧名称约束。离线恢复在本机重新核对 UUID／名称、大小，并在 Recovery 中再次解析目标，不直接回放旧 `sdfN` 编号；离线、未挂载、刷前留存和刷后回读检查仍生效。调试仅进行脚本语法检查，不执行恢复。

进入模块时比较已有备份与当前发现范围。覆盖不足时新增一组备份并上传，保留原始基线，另记录当前覆盖清单；全量恢复优先使用覆盖当前范围的完整组，不将缺分区的旧组作为完整恢复。运行时发现依赖系统暴露的物理分区和实际服务引用，不能证明隐藏、未使用且无可识别线索的存储一定存在于备份。

按用户要求，备份失败后两个入口均可显示“强制跳过”。红色警告窗口列出当前识别分区（识别失败时提示仅供参考），建议先通过“多系统工具箱”“爱玩机”等另行备份，并明确基带崩溃、IMEI 丢失、无信号和无法恢复的风险。继续按钮锁定 5 秒，ViewModel 使用单调时钟再次校验；取消或重新打开会重置等待。确认仅为当前应用会话放行备份门槛，记录风险日志，不伪造本地或云端备份成功，也不自动启用写入。用户仍须手动开启修改。高通平台、权限、功能原值与恢复包完整性检查不因跳过而取消。

导出/分享通过同一脱敏 JSON 生成器，始终屏蔽 IMEI、IMSI/ICCID、序列号、令牌/密码、URL 参数、IP/MAC、手机号/邮箱、坐标及原始十六进制载荷，仅授予所选分享目标临时读权限。公开的 APK SHA-256 和实际堆栈帧中的 R8 映射标识保留，其他哈希类敏感字段继续屏蔽。IMEI 明文仅用于 HTTPS 上报的独立字段，后台私有保存，不写入分享文件。

后端在 `C:\Users\Administrator\Desktop\NetworkHelperBack`，接口 `/networkhelp/diagnostics/register`、`/networkhelp/diagnostics/reports`、`/networkhelp/diagnostics/console` 均为 POST。**每小时归档需同步发布 server.js、diagnostics.js、diagnostic-storage.js、diagnostic-archive.js、find-diagnostic.js 并重启服务**。复用现有 OSS 凭据，新增日志前缀的上传、读取和 ACL 查询权限；后台启动时及每个整点上传并核验私有压缩文件，本地硬保留 7 天、默认压缩日志额度 1 GiB。容量不足返回 503 并尝试腾出已归档日志空间；超过 7 天即使未归档也会删除并告警。OSS 副本不自动清理，回执查询可从 OSS 找回已清理的本地日志。部署及归档状态检查见后台 diagnostics-api.md。

客户端可运行定向单元测试验证编译，无需执行 assemble 或生成 APK；诊断验证保持只读。后台测试使用临时目录和 OSS 替身，不上传真机日志或操作真实 OSS。
