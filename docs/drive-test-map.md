# 路测地图：双卡记录与附近基站

适用于源码 v1.5.3 / versionCode 53。

## 绘制与探测设置

路测地图 FAB 中原“扇区绘制参数”已扩展为“地图绘制与探测参数”，在可滚动对话框中同时设置：

- 扇区角度、绘制距离和路测采样间隔。
- 附近基站自动探测开关，默认关闭。
- 探测半径 1–10 km，默认 3 km。
- 制式：全部、4G (LTE)、5G (NR)。
- 可选 Band：留空、数字、`B` 或 `n` 前缀，例如 `3`、`B3`、`n78`。

保存后设置在下次进入时保留；“立即探测”可发起一次查询。开启自动探测后，定位回调按时间和移动距离节流查询，地图暂停时不发起自动查询。圆圈显示查询半径，状态文字显示结果或失败原因。

| 制式 | Band | 显示范围 |
| --- | --- | --- |
| 全部 | 留空 | 所有 4G / 5G 频段 |
| 4G | 留空 | 所有 4G 频段 |
| 5G | 留空 | 所有 5G 频段 |
| 4G | 3 或 B3 | 4G B3 |
| 5G | 78 或 n78 | 5G n78 |
| 全部 | 3 | 4G B3 + 5G n3 |
| 全部 | B3 | 4G B3 |
| 全部 | n78 | 5G n78 |

制式与 Band 前缀冲突时不提交设置。后台不支持的 Band 会显示提示。更改筛选会清除旧结果并按新条件查询。

这些结果来自工参库，覆盖取决于库中已有坐标。客户端将地图 GCJ-02 坐标转换为 WGS84 查询，返回结果转换到地图坐标绘制。后台先筛选制式、频点与圆形距离，再按距离排序，每种制式最多返回 1000 个小区；达到上限时提示缩小范围。地图按站址合并展示，因此站数与小区记录数可能不同。

Band 按 EARFCN / NR-ARFCN 范围判断。NR 频段范围存在重叠，例如 n77/n78；筛选结果不能单独证明基站实际配置的 Band。

## 双卡录制与回读

每次采样使用同一定位与时间戳收集两张卡的可用快照，并以一个批次写入 Room。当前选择的 SIM TAB 只决定地图和面板显示哪组数据，两张卡都会记录。停止保存或丢弃 Session 前等待待写入批次完成。

进入地图时显示实时数据和当前位置，不自动读取历史 Session。通过 Session 列表主动“恢复”记录后：

1. 读取整段记录并按 SIM 分组。
2. 将视角移到整段记录最早的有效打点位置。
3. 用 SIM TAB 切换面板和轨迹数据组；历史显示不混入后续实时信号更新。

旧单卡记录仍可读取，未记录的另一张卡不会生成历史数据。无法取得快照的 SIM 也不会补造记录。开始新的路测切换回实时采样；定位与电话权限需要按提示授予。

## 后台接入

后台：[NetworkHelperBack](https://github.com/mazemingw/NetworkHelperBack)，Apache 2.0。

接口为 `POST /networkhelp/cell-params/nearby`，携带 WGS84 的 `latitude`、`longitude`、`radius_km`，以及可省略的 `rat`、`band`。完整协议与错误码见 [接口说明](https://github.com/mazemingw/NetworkHelperBack/blob/main/nearby-api.md)，环境配置和部署见后台 README。

已有工参数据库不需要为本功能改表。服务端需包含 `nearby.js`、`nearby-bands.js`，并由 `routes.js` 注册路由；更新后重启服务。本次只推送源码，没有重启线上服务。

## 验证与手工测试

本次完成 Android 单元测试与 Debug 构建、后台接口回归测试及现有数据库的半径/频段查询核对。没有安装到设备或进行设备调试。

建议手工检查：

1. 已有多个 Session 时进入地图，确认仍位于当前位置。
2. 双卡录制时保持一个 TAB，停止保存后恢复，确认另一个 TAB 也有记录。
3. 恢复位于远处的 Session，确认镜头移到最早打点；再切换双卡和读取旧单卡记录。
4. 分别查询全部制式、仅 4G、仅 5G，并测试留空 Band、数字和前缀 Band。
5. 将半径设为 1 km 和 10 km，检查范围圆圈及结果刷新；尝试冲突前缀与不支持的 Band，检查提示。
