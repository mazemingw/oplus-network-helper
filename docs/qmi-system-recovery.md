# 系统 NAS 客户端耗尽与清理通道

2026-10-29，适用于 1.6.1 (61)。实现位于 `SystemQmiServices.kt`、`system-services.sh`、
`ModemDriversViewModel.kt` 和 `SystemQmiRecoveryDialog.kt`。

## 证据与适用范围

用户提供的《QMI端口诊断报告》《QMI系统组件说明与停启命令》是诊断材料，文中的命令不作为本次自动操作手机的授权。
PLK110 / PLK110_17.0.0.105(CN01) 的对照试验显示：NAS 容纳六个并发客户端，
两路 QCRIL、两路欧加无线扩展各持有一个，qms 持有两个。暂停 qms 释放两个；
仅暂停 qti-modem-daemon-1 释放一个。该容量、计数与 QRTR 地址不推广为所有固件的常量。

最新报告中特别注明：qti-modem-daemon-1 已由用户在助手之外停止。本功能不会把它记为助手暂停，
退出自动恢复也不会启动它；用户仍可明确点击“恢复此组件”。不读取或套用固件专属 QCCI 内存偏移，
也不把一般 QRTR 描述符数标成 NAS 数。弹窗列的是报告已确认的 NAS 使用组件及其实时 init 状态，
不是实时 NAS 所有者枚举；其它固件只显示身份核对结果，不展示该设备的历史数量。

## 清理与选择

普通清理仍先释放助手连接及已核实的第三方占用者，不杀系统服务。随后等待当前后端实际读取完成。
原有驱动同时保留控制 NAS 客户端，再建立监测客户端读取，验证两路同时可用，而非先释放一个再验证另一个。
bunnylock 按其当前后端读取结果判断，不强制要求 AT / HAL 持有两路 NAS。
失败时弹出组件面板，展示服务名、PID、运行状态、身份核对、用途、暂停影响与助手暂停归属。

“替我决定”默认开启：仅在确认客户端耗尽时预选两路可暂停的欧加无线扩展。
用户点击“暂停所选并重试”后才执行。按实例 1、实例 0 的顺序逐项暂停、有限等候释放、重新读回；
一旦验证成功便停止，不固定停两个服务。其它错误不继续扩大暂停范围。
qms 与 QCRIL 从不自动选择；手动选择需要勾选影响确认。
可逐个恢复，也可只恢复助手暂停的全部组件。

组件作用：

| 服务 | 已知用途 | 暂停影响 |
| --- | --- | --- |
| qti-modem-daemon-0 / 1 | subsys_daemon 加载 libqti-radio-service.so，欧加小区、NRCA、频段/小区与 QoS 扩展 | 对应实例的工程模式及厂商优化可能降级；实例不保证映射物理 SIM |
| vendor.qms | Smart Transmit、SAR/无线共存、数据、NTN 等模块 | 射频协同、数据与厂商功能可能受影响 |
| vendor.qcrild / vendor.qcrild2 | qcrilNrd 核心电话接口 | 注册、语音、短信、IMS 和数据可能中断 |

只接受固定服务目录，并核对本机 init 定义、可执行路径和运行进程参数。
不匹配即禁用，不猜测其它设备的同名进程。使用 `ctl.stop` / `ctl.start`，
不 SIGSTOP 系统进程、不修改 rc、不永久禁用、不更改 SELinux、不使用全局 stop。
init 控制和状态依据 [AOSP init 文档](https://android.googlesource.com/platform/system/core/+/refs/heads/main/init/README.md)。

## 自动恢复

“自动恢复”默认关闭，位于“驱动&设置 / 射频与通道”。关闭时保持用户选择，可手动恢复。
开启后只恢复助手本次暂停前确实正在运行、且属于当前 boot_id 的服务。
暂停前先持久化归属日志，写入失败不暂停；恢复失败保留记录和日志，不能误报已经恢复。

正常退出通过最后一个 Activity 的 finishing 回调触发，切后台、旋转及应用内切换 Activity 不触发。
还启动独立 Root guardian，检查应用 PID 与启动时间，对进程死亡提供恢复兜底。
恢复前取消监测、释放控制会话，再关闭核实属于本 APK / UID 的孤立辅助进程，最后恢复系统组件。
Root guardian 依赖 Root 管理器允许独立进程存活；如果系统连同 guardian 一起终止，无法保证即时恢复，
下次启动开启自动恢复的助手时会先处理遗留日志。重启后的旧 boot_id 记录不启动服务。
init 显示 running 仅代表进程启动，不承诺所有厂商接口已完成初始化。

## 本次验证与真机验收

按用户要求只进行编译与脚本语法检查，没有在手机执行系统服务停启，也未安装 APK。
Debug 构建：`gradlew.bat :app:assembleDebug`；脚本语法：`bash -n app/src/main/assets/qmi/system-services.sh`。

真机按需检查：普通清理失败出现弹窗；原已停止项不自动选中；确认暂停后读回控制和监测；
成功后不继续暂停剩余项；退出 / 进程死亡在自动恢复开启时恢复助手暂停项；
自动恢复关闭、切后台和旋转时不恢复；手动恢复后若资源再次耗尽，应保留真实读取错误。
本次编译通过不等于以上 Root / init 行为已经完成真机验收。
